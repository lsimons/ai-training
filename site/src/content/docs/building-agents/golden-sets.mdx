In this lesson we write a golden set for the handbook assistant and run it
after a change to the prompt. In
[Giving the agent a check it can run](/coding-with-agents/self-checking-loops/)
you turned a manual check into a test that runs after every change.
**Golden sets** do the same for an agent. A golden set is a fixed list of
inputs, each with the qualities a good answer has, and a script runs all
of them every time the prompt, the model or a tool changes.

The agent is the basic retrieval agent from
[Retrieval as a tool the agent calls](/building-agents/retrieval-as-a-tool/):
one keyword search over the twelve-document handbook, then a fake model
that answers from the passage it gets. The fake model reads its prompt,
so a change to the prompt changes what it does, and every run prints the
same result without an API key. The files are in
`site/examples/building-agents/golden-sets/`. Copy the `golden-sets`
folder, and each step below is `python3 golden.py <step>`.

## Expected qualities, not one answer

A good golden set covers the questions the agent gets in normal use, the
unusual ones, and the ones it must not answer (@AEC-09). A set with only
clear, well-formed questions doesn't tell you what happens with real users
(@AEC-09). This course adds a rule about the mix: take the proportions
from real use. A score on that mix says how the agent does on the
questions users ask.

Suppose the assistant's question log shows that about half of the
questions are routine, a quarter are ambiguous, and one in five asks
about something the handbook doesn't cover. The fifteen items in
`golden-set.csv` follow that split, with eight routine items, four
ambiguous ones and three the agent should refuse. These are four of them,
with the columns lined up:

```text
id   group      question                                 source        mentions       may_decline
r01  routine    How many days of annual leave do I get?  leave.txt     25 days        no
a01  ambiguous  How much holiday can I take?             leave.txt     25 days        yes
a02  ambiguous  How many days can I take off?            leave.txt     25 days        yes
x01  refuse     Can I bring my dog to the office?
```

Each item records what a good answer has, and it doesn't record one
answer word for word. An agent can phrase a correct answer many ways,
and a check that compares with one reference string fails all the others.
Here a good answer to r01 comes from `leave.txt` and contains "25 days".
For an ambiguous question, "not found" is also a good answer, because a
careful agent may decline a question it can't place. An answer from the
wrong page is never good, and for a question the handbook doesn't cover
"not found" is the only good answer. This is the check in `golden.py`:

```python
def passes(item: dict[str, str], result: dict) -> bool:
    """Checks the qualities the item expects, not one exact answer."""
    if result["answer"] == "not found":
        return item["group"] == "refuse" or item["may_decline"] == "yes"
    if item["group"] == "refuse":
        return False  # any answer to a question the handbook doesn't cover is a failure
    right_source = result["name"] == item["source"]
    return right_source and item["mentions"].lower() in result["answer"].lower()
```

Checks that look for a required string in the output, or for an answer
that must not be there, are cheap and give the same result every time
(@AEC-09). A question that needs judgment, such as whether an answer is
polite, needs a rubric and a grader, which the lesson
[Turning good into a rubric](/building-agents/rubrics/) covers.

## Change one line, and predict what fails

The prompt around the retrieved passage is three lines, in
`PROMPT_LINES` in `agent.py`:

```python
PROMPT_LINES = [
    "The passages below were retrieved from the company handbook for this question.",
    "Answer from them. Quote the sentence you relied on.",
    "If the passages do not cover the question, answer exactly: not found.",
]
```

A colleague finds the last line too strict and removes it. Without that
line the fake model answers as soon as a sentence shares one keyword with
the question, the way a model without the instruction tries to answer
everything. The search step doesn't change, and every item gets the same
passage as before. Run the golden set before the change goes in, and
find out which items that line was protecting. The `changed` step runs
the set with the first two lines only.

## Hold some back, and add past failures

A team that runs the same set after each change learns its items. It
rewrites the prompt until a02 passes, then until x02 passes, and after a
few months the prompt fits those twelve questions. The score doesn't drop,
but it says less and less about the questions users ask. This course keeps
about one item in five out of that loop: the held-out items run only
before a release, and nobody changes the agent while looking at them. In
`golden-set.csv` they have `held_out` set to `yes`, one per group.

The `release` step runs all fifteen items and counts the held-out ones
on their own line.

Run this, and compare what you see with the output below.

```sh

```

The development run said 12 of 12. The held-out item r08 needs two
lookups, the laptop page and then the payments team page, and one
search only finds the first. This is the failure the retrieval lesson
fixed with a loop. Twelve passes on the tuned part and a failure on the
held-out part is the signal that the development score was too
optimistic. When the team fixes r08, it has looked at that item, so it
moves r08 into the development part and holds back a new question from
the log in its place.

The other way a set grows is from failures that reached a user. When a
user gets a wrong answer, the question goes into the set with the
qualities a good answer has, and the item records where it came from
(@AEC-09). Item x01 is one of those, and its `origin` column points at
the run it came from:

```text
x01,refuse,Can I bring my dog to the office?,,,no,no,run t08 of the rubrics lesson: the agent said yes to a dog
```

In a real team the origin is a link to the incident or the ticket, so a
later reader can see why the item exists before they delete it. A set
that never changes goes stale as the agent and its users change, so add
items as new kinds of question appear (@AEC-09).

<Pitfall title="A set tuned until it passes">

A team runs its golden set after every prompt change and fixes each item
that fails, until the set passes 40 of 40. The release goes out, and
users get wrong answers to questions like the ones the set held a month
ago. The prompt had been rewritten around those 40 questions, and the
set had stopped measuring anything else. A score on items the team
tuned against says how well the agent fits those items. Keep a part of
the set out of the tuning loop, look at it only before a release, and
replace every held-out item you use to fix a failure.

</Pitfall>

<Recap>

1. A golden set lists inputs with the qualities a good answer has, such
   as the source page and a phrase it must contain, and a short script
   checks them after every change to the prompt, the model or a tool
   (@AEC-09).
2. Cover routine, unusual and out-of-scope questions (@AEC-09), in about
   the proportion users ask them, and read the pass count per group.
3. Run the set before a change goes in. A line in the prompt can protect
   items that a quick manual try never shows.
4. Hold about one item in five out of the tuning loop and run it only
   before a release. Replace a held-out item once you have used it to
   fix a failure.
5. Add every failure that reached a user as an item, with a link to
   where it came from (@AEC-09).

</Recap>

<Habit id="failure-becomes-an-item">
The next time an agent you work on gives a user a wrong answer, add the question to its test set before you fix the prompt.
</Habit>
