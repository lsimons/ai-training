In this lesson the fake model writes one line of reasoning before each
tool request, and the loop prints that line in the trace. We run one task
with the model that writes the line and with one that doesn't, and compare
the traces. After that we look at a task where the line changes which tool
the model asks for, and at what the line costs.

The loop is the one from
[Stopping the loop on purpose](/building-agents/stopping-the-loop/),
with the same `run` and the same stop rules. Its `show` prints one more
line, the thought, when a request has one. The complete
program is `site/examples/building-agents/react/agent.py` in the
repository. The tools belong to a small shop. `get_order` returns the
item and the days since delivery, `get_policy` returns the text of a shop
policy, and `issue_refund` refunds an order in full.

## One line of reasoning before each call

The pattern has a name, ReAct, from the paper that tested it: the model
alternates a short written reasoning step with an action, reads the
result, and reasons again (@Yao 2022). In the paper, the reasoning helps
the model keep and update a plan, and handle surprises, and the actions
fetch the facts that the reasoning needs (@Yao 2022). The lesson on
agentic design patterns in the Agent Engineer Course presents it as a
loop of think, act, observe (@AEC-04).

In the fixture, the reasoning is one more field in the reply. The fake
model `model_reasons` writes a `thought`, then asks for the tool that
follows from it. Here is its first round:

```python
if len(done) == 0:
    if question.startswith("Refund"):
        thought = "A refund is allowed only inside the return window, so I check the order first."
    else:
        thought = "A return depends on when the order arrived, so I look up the order."
    return {"thought": thought, "tool": "get_order", "args": {"order_id": order_id}}
```

In the second round it reads the days since delivery from the result and
asks for the return policy. After that it compares the two numbers and
answers. `show` prints `thought:` and the text before the round line of
every request that has one.

## The loops in this course already alternate

The loops in this course already alternate a model decision with an
action and its result: the model decides on an action, the loop runs it,
and the model decides the next action from the result. The pattern adds
the written reason between the result and the next decision. Some models
write that reason on their own. On Claude, a model that supports
interleaved thinking can write its reasoning after each tool result and
before the next call. The API returns that reasoning as a summary, or as
an empty field when the `display` setting is `omitted`, and it bills the
full reasoning in both cases (@Claude docs thinking). The choice you
make as the builder is whether the reasoning appears in a form you can
read and keep.

A task gains from the extra tokens when its next step depends on what an
earlier result said. The agent then chooses between tools as it goes.
The refund is such a task: the order decides whether the refund tool is
right. When the calls are the same whatever the results say, as with one
export per table every night, the line doesn't change a call, and a
fixed script or a plan fits the job better. People who review or debug
the runs have a second reason to keep the line, because it shows them
where the agent went wrong.

<Pitfall title="Reading the thought as a record of what happened">
A reviewer sees "I check the order first" in a trace and concludes that
the agent checked the order. The thought is text the model wrote. In the
fixture's `run`, the loop runs `reply["tool"]` with `reply["args"]` and
never reads `reply["thought"]`, so a thought and a call can disagree and
the loop runs the call. Research on written reasoning found that models
leave out factors that changed their answer and write plausible reasons
for answers they were pushed toward (@Turpin 2023). On Claude, the
thinking you get back is a summary or an empty field, and no display
setting returns the raw reasoning (@Claude docs thinking). Rule: check
what the agent did in the round lines, the calls and their results, and
read the thought as the model's explanation of them.
</Pitfall>

<Recap>

1. ReAct alternates a short reasoning step with an action and reads the
   result before it reasons again (@Yao 2022).
2. On a task with a fixed path, the reasoning line adds a readable reason
   for each call and leaves the calls the same.
3. When the next tool depends on an earlier result, the reasoning step can
   change which tool the model asks for, at the cost of one more line per
   step that the loop sends back in every round.
4. A tool-using loop already alternates decisions and actions, and on
   Claude a thinking model can reason between tool calls whether or not
   the loop shows it (@Claude docs thinking). A shown thought can leave
   out what drove the choice (@Turpin 2023), and the round lines are the
   record of what the loop ran.

</Recap>
