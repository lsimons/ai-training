An earlier lesson in this part covered the agent's memory notes and the
context files it reads at the start of every session. This lesson is about
what happens inside one long session, when the conversation gets too long
for the window and the agent replaces it with a summary. We load a session log with three facts planted
in it and compact it on command, with instructions for what the summary
must keep. Then we check which facts are still there.

The lesson uses Claude Code, and the files are in the course repository at
`site/examples/customizing-agents/compaction/`. `transcript.md` is the
session log. `check_summary.py` is a short Python script that only reads the
file you give it, and the course checks its output on every build. Run the
commands in this lesson from that directory. In the `cd` line, replace
`<course-repo>` with the path to your copy of the course repository.

```sh
cd <course-repo>/site/examples/customizing-agents/compaction
```

## A long session, and a summary in its place

[Where memory comes from](/concepts/memory/#when-the-window-holds-too-much)
described context rot: as a session goes on, the window fills with old
turns and tool output, and the model starts to lose facts that are still in
the window (@AEC-05). A long coding session gets there fast, because every
file the agent reads and every test run adds to the window.

**Compaction** is the way out that keeps you in the same session. The agent
replaces the conversation so far with a summary and goes on from the
summary. The summary is much shorter than the turns it replaces, and it
keeps the goal and the recent state. The raw detail is gone, and so is
anything else the summary leaves out. The model that writes the summary can
miss something important (@AEC-05).

In Claude Code, compaction happens in two ways. It runs by itself as the
window gets close to its limit, and the session goes on after it
(@Claude Code context window). You can also run it yourself with the
`/compact` command and add instructions for the summary after it, as in
`/compact keep the decisions about the export route` (@Claude Code commands).
The instructions tell the summary what to keep. Without them, the automatic
pass decides for itself what matters (@Claude Code context window).

## What the summary replaces, and what comes back

Some of what the agent knows doesn't depend on the summary. Claude Code
keeps these outside the conversation and puts them back after a compaction
(@Claude Code context window):

- the project-root `CLAUDE.md` and the auto memory notes, read again from
  disk
- the plan the agent wrote in plan mode, read again from disk
- up to five of the files the agent read or edited, the most recently
  modified first

Everything that was said in the conversation goes into the summary, and
that includes a rule you typed in the chat. Claude Code's memory page says
that an instruction that disappeared after compaction was given only in the
conversation, and that a rule you want to keep belongs in `CLAUDE.md`
(@Claude Code memory). A rule with `paths:` in its front matter, or a
`CLAUDE.md` in a subdirectory, is loaded into the conversation when the
agent reads a matching file. So it is summarized away too, and comes back
only when the agent reads such a file again (@Claude Code context window).

So a compaction puts at risk each fact that exists only in the chat. In
this lesson that means a rule you set, a decision with its reason, and an
open item that nobody wrote down. The log plants one of each.

## Load the session

The log in `transcript.md` is a coding session on a small report service,
written for this lesson. Read it once. It plants three facts:

- a rule the user sets in the first message: don't change anything under
  `migrations/`
- a decision from the middle: keep the old `/v1/export` route until March
  31, because version 4.2 of the mobile app still calls it
- an open item from later on: the test `test_export_timezone` fails, and
  the user wants it fixed after the release

Make an empty folder for the practice session and start Claude Code in it.
The folder has no project files, so the agent has nothing to change and
answers only from the conversation.

```sh
mkdir -p ~/compaction-practice
cd ~/compaction-practice
claude
```

Open `transcript.md` in an editor, copy the whole file, and paste it as your
first message. Then ask one or two questions about it, such as "What does
`to_json()` do?" and "Which test did the agent add?". Paste the log and
don't ask the agent to read the file, because after a compaction Claude
Code reads recently used files again (@Claude Code context window), and a
file the agent read would bring all three facts back. In a session with
too little history, `/compact` answers `Not enough messages to compact.`
(@Claude Code costs). If you see that, ask another question.

Before you compact, write down which of the three facts you expect a
summary without instructions to keep. Then look at the file
`samples/unguided.md`. It is a summary of the same log that shows how a
summary without instructions might read. The course wrote it for the
lesson, and no model produced it. The script `check_summary.py` looks for
the words that name each fact and prints `kept` or `lost`.

## Compact on command, and check

Now compact with instructions that name the kinds of facts at risk. In the
practice session, type:

```text
/compact Keep every decision with its reason, every open item, and every rule I set for this work. Drop the tool output.
```

Claude Code writes the summary without showing it and prints a message
that the conversation was compacted (@Claude Code context window). You
can't read the summary itself, so you check it by asking. Work on this
project goes on in another session, so have the agent write the answer
to a file:

```text
Write summary.md with the goal of this work, the current state, every decision with its reason, every open item, and every rule I set. Use only what you know from this conversation.
```

The agent writes `summary.md` from the compacted summary, because the
summary has replaced the log in the conversation
(@Claude Code context window). Leave Claude Code with `/exit`, and go back
to the course directory to check the file:

```sh
cd <course-repo>/site/examples/customizing-agents/compaction
python3 check_summary.py ~/compaction-practice/summary.md
```

The course repository has a summary written for the lesson with the same
instructions, in `samples/directed.md`. Run the script on it to see the
output that a summary with all three facts gives.

## Where a fact belongs

A summary is right for the work of one session. A fact that every session
needs belongs in a file that compaction doesn't touch. For a rule such as
"don't change anything under `migrations/`", that file is the
project-root `CLAUDE.md`, which Claude Code reads again after every
compaction (@Claude Code memory). You can also add a section to
`CLAUDE.md` that says what every compaction must keep, for example the
list of changed files and the test commands, and Claude Code uses it when
it compacts (@Claude Code best practices) (@Claude Code costs).

The `summary.md` you saved is for the next session on the same work.
A new session, or a `/clear`, starts with an empty conversation
(@Claude Code commands), and the file is the part of this session it can
read. The next lesson in this part turns that file into a full handoff.

<Pitfall title="The summary that kept everything except the decision">
A developer works all afternoon in one session. Early on they decide to
keep an old route until a mobile app version is retired, and say so once
in the chat. The session compacts by itself, and its summary lists every
changed file, the tests and the next step, all of it correct. The decision
isn't in it. An hour later the agent removes the old route as dead code,
the tests pass, and the app stops working the next morning. Before you
compact, tell the summary to keep decisions, open items and rules, and ask
the agent afterwards what it still knows.
</Pitfall>

1. Compaction replaces a long conversation with a summary that keeps the

   (@Claude Code context window).
