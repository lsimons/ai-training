In this lesson we read the notes a coding agent keeps for itself and
clean them up. The notes belong to the to-do project from earlier lessons,
and four of them are planted for you: one is still right, two have gone
stale, and one holds a fact the whole team should have. You delete the
stale two and move the team fact into a file in the repository, where
it is versioned and reviewed like code. On the way you meet the import
syntax that pulls such a file into the agent's instruction file.

Where the notes are kept, what loads when, and the import syntax are
Claude Code's, checked against the vendor's documentation on the date at
the end of the lesson (@Claude Code memory). Other coding agents keep
notes under other names and in other places. The review works the same
way there.

## Where the notes are

**Auto-memory** is the set of notes an agent writes for itself during a
session and reads back in later sessions. Claude Code calls its version
auto memory, and it is on by default. Claude writes the notes itself,
from your corrections and preferences and from facts about the project
that it can't work out from the code. A person writes the instruction
file, `CLAUDE.md` or `AGENTS.md`. Both kinds of file are loaded at the
start of every session, and Claude treats them as context, the same way
it treats a message you type. The model weighs them as it weighs any
other text, and Claude Code doesn't enforce them (@Claude Code memory).

Each project gets one memory folder, `~/.claude/projects/<project>/memory/`
on your machine. Claude Code derives `<project>` from the git repository,
so every worktree and subfolder of one repository shares the folder. The
folder is on your machine only. A colleague's machine has a folder of its
own, and the notes aren't shared between machines (@Claude Code memory). Inside are an index
file, `MEMORY.md`, with one line per note, and one topic file per note.
Each topic file is Markdown with a short header, and its `type` field
names one of four kinds: `user` for your role and preferences, `feedback`
for corrections you gave, `project` for ongoing work and decisions, and
`reference` for where to find things outside the project
(@Claude Code memory).

A session doesn't read the whole folder at the start. It loads the first
200 lines of `MEMORY.md` or its first 25KB, whichever limit comes first,
and it reads a topic file only later, when the work needs it
(@Claude Code memory) (@Claude Code context window). So the index line is
what every session sees, and a wrong index line is wrong in every
session.

The planted notes are in the course repository at
`site/examples/customizing-agents/memory-review/notes/`. The program
`startup.py` next to that folder applies the loading rule to them. Its
complete source is in the same folder.

## Delete what has gone stale

A remembered fact doesn't warn you when it goes out of date. Long-term
notes need updating as the world changes (@AEC-05), and nothing in the
feature does that for you. The index line is in the window at the start
of every session, and the model reads it as context like anything else
there. A note that was right in June and wrong in September is applied
in September as firmly as in June, in every session, until someone edits
it. Claude Code keeps the notes until you or Claude change or delete them
(@Claude Code memory).

So check each note against the thing it describes. The two `project`
notes about `done()` and the tests make claims the copy can confirm or
contradict. The rewrite note names a branch.

```sh
git branch --list done-v2
```

The command prints nothing: there is no `done-v2` branch, and the rewrite
the note waits for isn't happening here. The test note says the tests
write `todos.json`.

```sh
grep -c todos.json test_todo.py
```

It prints `0`. The tests build their items in memory and never open the
file, and `AGENTS.md` says as much: "the tests use a temporary file". Both
notes were true once, before plans changed, and both now make the agent
do the wrong thing. One makes it refuse a bug fix, and the other makes it
copy a file the instructions say to leave alone.

Delete both topic files, `project_done_rewrite.md` and
`project_tests_touch_data.md`, in the folder `/memory` opened, and delete
their two lines from `MEMORY.md`. The notes are plain Markdown that you
may edit or delete at any time (@Claude Code memory). Delete the index
line as well as the file, because the index line is the part that loads.

## Move a team fact into a context file

The diff note and the item length note are left. "Show the diff before explaining a change" is one
person's working preference, and a personal note is what auto memory is
for. "Keep item text at 80 characters or fewer" is different. It is a
decision about the product, because the phone widget cuts longer text
for everyone. Each person on the team needs it in each session, on each
machine. In auto memory it reaches only the agent on this one
machine, and nobody reviews it.

**Context files** are the files a person keeps for the agent to read:
project instructions, design notes, a plan, a glossary. They are in the
repository, so a change to one is a commit that someone can review, and
every clone has the same text. The team fact belongs in one. The fixture
has an `AGENTS.md` and no `CLAUDE.md`, and in that case Claude Code
reads `AGENTS.md` as the project instructions (@Claude Code memory).
You could add the rule to `AGENTS.md` directly. For a decision that has a
reason and a date, a notes file of its own keeps `AGENTS.md` short, and
the import syntax loads it with `AGENTS.md`.

To import another file, an instruction file names its path after an `@`
sign, for example `@docs/decisions.md`. Claude Code expands the imported
file and loads it into context at launch, together with the file that
imports it. A relative path is
resolved from the folder of the file that holds the import, not from the
folder you started the agent in. An imported file may import further
files. Claude Code skips an `@path` inside a code span or a fenced code
block. Writing `` `@README` `` in backticks mentions the file and doesn't
load it
(@Claude Code memory). Imports also work inside an `AGENTS.md` that
Claude Code reads directly (@Claude Code memory).

Here are those rules as a small program, applied to a sample project in
`site/examples/customizing-agents/memory-review/imports/`. The complete
file is `imports.py` in the same folder. The project's `AGENTS.md` is:

```markdown
# Agent instructions for todo

- Python 3, standard library only. No new dependencies.
- Run the tests with `python3 -m unittest -q`.
- Add a line to `@CHANGELOG.md` for every change a user can see.
- Team decisions that the code doesn't show: @docs/decisions.md
```

`docs/decisions.md` holds the 80-character rule and the line "The words
used here are defined in @glossary.md". The project has two glossaries:
`glossary.md` at the top, an old one, and `docs/glossary.md`, next to
`docs/decisions.md`. It also has a `CHANGELOG.md` at the top.

`CHANGELOG.md` isn't loaded, because its `@` is inside backticks. That
line only names the file. The glossary that loads is the one in `docs/`,
because `@glossary.md` is in `docs/decisions.md` and resolves from

window like the file that imports them. An import organizes the files,
and it doesn't save context (@Claude Code memory).

Now do the move in your copy. Create `docs/decisions.md`:

```markdown
# Decisions

- Keep item text at 80 characters or fewer. The phone widget that shows
  the list cuts longer text.
```

Add this line at the end of `AGENTS.md`, with nothing after the path:

```markdown
- Team decisions that the code doesn't show: @docs/decisions.md
```

Then delete `project_item_length.md` and its line from `MEMORY.md`, so
the fact is in one place. Commit the two repository files, which is the
step that makes the fact reviewed and shared.

```sh
git add AGENTS.md docs/decisions.md && git commit -q -m "Record the item length decision"
```

command. Run `/context` and look at the list of memory files, which shows
the instruction and memory files the session loaded (@Claude Code memory).

answer names `docs/decisions.md`, and the notes folder holds `MEMORY.md`
with one line and `user_diff_first.md`. Memory notes and context files

<Pitfall title="The note that skipped the tests">
A team's test suite once took ten minutes, because it ran against a
shared database. A developer told the agent to run only the test for the
function it changed, and the agent saved that as a memory note. Months
later the tests used an in-memory database and finished in two seconds,
and nobody edited the note. The agent kept running one test per change,
and a change to one command broke another command's test. CI caught it a
day later. Any note that lets the agent skip a check deserves a check of
its own at every review, and a date inside the note tells a reviewer how
old the claim is.
</Pitfall>

<Recap>
1. Auto memory is notes the agent writes for itself. In Claude Code they
   are in one folder per repository on your machine, with a `MEMORY.md`
   index and one topic file per note, and the feature is on by default
   (@Claude Code memory).
2. A session loads the first 200 lines or 25KB of `MEMORY.md` at start,
   and reads topic files only when it needs them. The index line is what
   every session sees (@Claude Code memory).
3. A stale note is applied in every session with the same confidence as a
   true one, because the model reads it as context. Check each note
   against what it describes, and delete the file and its index line.
4. A fact the whole team needs belongs in a context file in the
   repository, where it is versioned and reviewed. An instruction file
   loads it with `@path`, resolved from the importing file's folder, and
   a path in backticks stays text (@Claude Code memory).
</Recap>
