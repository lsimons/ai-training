## What review caught

- The first #220 build added a new hand-written tag scanner for its menu of
  examples, the kind of reader #98 removes. The reviewer showed that
  `title={'Run it'}` rendered verbatim and that a commented-out `<Predict>`
  became a phantom menu entry.
- `promptOf` in #98 paired a `<Prompt>` with the next `<Response>` in
  pre-order, so a prompt with any JSX child lost its response on the topic
  page. The reviewer built `main` and the branch and diffed every
  `checkpoints.json` entry, which confirmed that the three props whose indentation changed were
  the only intended change.
- A protocol-relative `//host` passed the new `extends-to` schema as an
  internal link, and the URL prefix match let `../` segments out of the
  bibliography entry (#85).
- The #282 multi-line code span let one stray backtick before a blank line
  shift every span in the next paragraph. The fix then stopped handling a
  span with a backtick inside it, which the re-check caught.
- The #279 check found a real bundle bug on `main`: blank lines inside
  fenced code were collapsed in 8 blocks across 5 bundles.
- The #58 builder reported the `CheckpointShell` doc comment as done on
  `main`, and it wasn't.
- The #69 bootstrap hardcoded the GitHub Pages base, so a local run would
  have been tutored from the published files.

## What the builder prompt should have said

- When a branch adds a reader or parser for lesson source and another
  branch in the wave replaces all such readers (#98 here), say that the new
  code must use the new reader and start from that branch. The #220 builder
  was told only to keep the `checkpointsOf` signature.
- Name, per branch, the files a sibling branch also edits, and where in the
  file the sibling's edit sits. The integration conflicts came from test
  files and import blocks that no collision note named.
- A builder that says an item is "already done on `main`" quotes the line
  that shows it.
