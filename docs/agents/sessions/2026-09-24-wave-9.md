## What the builder prompt should have said

- Run `mise run site-format` and then `site-lint` after the last edit and
  before the push. The #68 builder reported `site-lint` green on a branch
  that failed it.
- A builder that rewrites a checkpoint option re-reads that option's `why`
  and feedback text in the same edit. Three of the #234 audit rewrites
  broke that agreement.
- A change to markup that a Starlight client script reads (the sidebar's
  `details` and `summary`) needs a test that starts from the state the
  script restores, and not only from a fresh page.
- A change that removes or changes something a reader sees on the deployed
  site (a footer date) says so in the spec and in the issue comment, even
  when the issue only asks to decouple two fields.
- For reviewers: give the `code-review` skill an explicit target (the
  branch, or the worktree and the range `origin/main...HEAD`). One reviewer
  found the skill had reviewed the main checkout's empty diff. The lead
  added the line to the reviewer brief after the first reviews.
