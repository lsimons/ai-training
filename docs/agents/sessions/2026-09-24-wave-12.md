## What review caught

- The first #281 rule divided by the items left after exemptions, so an
  exemption on an item that wasn't at the hot position could make a lesson
  fail, and the same exemption was then reported as stale.
- The #285 test hard-coded the site origin, so a change of `site` in the
  Astro config passed against a stale SKILL.md.
- The #289 parser claimed that Vale keeps the last value of a repeated key. Vale joins
  repeated list keys, so a second `TokenIgnores` line would have passed the
  check while the two configs differed.
- The #295 package check dropped a bare package name that sat next to a
  `.zip` URL on one `Packages` line, silently.
- The #70 copy button on the `/tutor` line was clipped out of view at every
  width, and the text read `settingspage` because Astro drops the newline
  before an `<a>` at the start of a source line. The first fix moved the
  lost space to the other side of the link.
- The #296 docs said all three rejected forms break because of the citation
  split. Only the citation case does, since the renderer leaves the other two forms as literal text anyway.

## What the builder prompt should have said

- In an `.astro` template, keep a link and the words next to it on one
  source line. The compiler drops the newline before or after a tag at a
  line edge, and the words run together in the built page.
- A code block with a copy button puts the button outside the scrolling
  `pre`, and the builder checks it at 390px in the built page.
- A parser for a vendor's file format (a Vale ini) names the vendor page
  for every rule it copies, such as how a repeated key merges.
