## What review caught

- The next lesson (`tool-errors`) said its loop was "the loop from the
  previous lesson with a few changes" and listed no removal of the error
  handling that #91 had just added, so a learner would read "a tool error
  never escapes the loop" and then meet a raw `KeyError` one page later.
- Three false claims about permission modes: only commands that "create or
  move files" skip the prompt in accept-edits mode (the vendor doc lists
  `rm`, `rmdir`, `sed` too), "each edit and each command stops for your
  answer" (the built-in read-only command set never prompts), and a
  pre-existing "by default a coding agent asks" that the new section
  contradicted.
- A Scenario whose read-only wrong option was defensible because the stem
  asked which mode to start in and the lesson itself teaches starting in
  read-only.
- A description of a third-party skill that put the transitive-dependency
  count in the wrong step and the risk rating on every package, and an
  exercise that had the learner run a skill whose last step removes packages
  and commits, in a project they work on, without a report-only instruction.
- A worked example whose arithmetic did not show the constraint it claimed
  (500 documents at 4 s each fits a nightly batch).
- Two sentences that linked the same EUR-Lex article twice.
- The one Vale warning a spec edit added, and an unexpanded `NC`.
- Two reflows that exposed `ai-tells.ConsequenceClause` errors the old
  ragged wrap had hidden from Vale (#248, #249), and the builders split the
  sentences instead of wrapping around the rule.

## What the builder prompt should have said

- A one-line fix commit still runs `spell` and `prose`. The prompt listed
  the checks for the first commit; say the fix commit runs the same list.
- When an issue names a lesson that is not live as the teaching lesson for
  an `assumes` entry, the lead decides the stand-in before dispatch and the
  builder records it in the plan file's `notes`, not only in the issue
  comment. The #107 reviewer asked for the in-file marker.
- A change to one lesson's fixture or loop can make the next lesson's prose
  wrong. Tell the builder to grep the course for pages that say "the
  previous lesson" or "the last lesson" and read them after the change.
- An exercise that runs a third-party agent skill states whether the skill
  changes files, and tells the learner to ask for a report only or run it
  on a copy.
- The S02 alignment table is at full width in several rows, so a new
  objective cannot always be added there without a reflow. Say that a skip
  with the reason in the issue reply is acceptable.
